# R4 group policy consumer

R3b's evidence stays immutable. R4 adds a small finite policy consumer while the
coordinator owns scientific endpoints, benchmark labels and group assignment, and
PRISM owns production capabilities and real Linux execution. Current algorithms
and fixtures are implemented; real benchmark fitting/transfer awaits frozen inputs
and complete measured panels. They do not establish learned chemical improvement.

## Reuse and additions

`calibration.empirical_model` still constructs a joint empirical distribution,
with optional equal family/group weights and equal task weights within a group.
`diagnostics.exact_program` still provides finite exact/myopic search. Optional
world-specific measured resource costs now preserve cost/outcome correlation;
terminal workflow resource bindings prevent free terminal scoring. Resource quotes
remain conservative hard reservation bounds, separate from measured costs.
Existing callers retain their previous defaults and schemas.

`transfer.py` provides:

- `GroupSplit`: freezes task/group/family and train/calibration/test assignment;
  rejects family or group crossings. Independence must still be scientifically
  reviewed; arbitrary distinct strings cannot establish it.
- `Catalog`: identical allowed queries, outcomes, dependencies, shared resources,
  terminal workflows, initial workflow, abstention, loss definition and cost unit.
- `checked_rows`: exact role membership and complete task-level paired outcomes,
  losses and actual costs. Every cell needs evidence references. Missing cost is
  unavailable, not zero. Failed/missing measurements require declared outcomes.
- `fit_policy`: group-weighted empirical loss plus measured-cost minimization,
  using only train rows. Learned conditional trees are saved/loaded with content
  hashes binding the split, catalog, training rows, baseline schedule, calibration
  prefix and objective. Their structure changes with training loss and costs.
- `next_action`: receives acquired query receipts only. It does not take a label
  row. Unsupported histories abstain and challenge model support. Real adapters
  must verify receipts against the journal and settle producer executions there.
- `probability_assessment`: scores frozen forecasts on calibration groups, with
  Brier/log loss, support failures and per-group results. Zero probability is
  reported as infinite log loss, never hidden by undocumented clipping. No
  automatic calibrated-probability or causal mechanism claim follows.
- `calibrate_policy`: selects a predeclared mixture toward supported calibration
  joint-outcome frequencies, reweighting existing training worlds only. It selects
  mixture weight by group Brier, then cost weight by a common frozen loss/cost
  tradeoff. It retains all candidate scores and curves. Unsupported joint results
  never receive invented scientific losses; positive training support remains.
  Calibration-selection scores are explicitly not independent test estimates.
- `evaluate_policies`: common offline replay of initial workflow, learned phi,
  copy-best, fixed static schedule, myopic and finite nonmyopic controls. Shared
  measured resources are paid once, including terminal scoring. Test evaluation
  requires a release bound to the frozen policy and split.
- `record_policy`: uses the existing ResearchJournal to verify diagnostic
  evidence and append the frozen policy without creating a shadow cost ledger.

The initial learned phi is the exact finite nonmyopic empirical-risk policy.
Those two reported controls are intentionally identical. A nonconstant tree is
not guaranteed, and equivalence is not an algorithmic advantage. Quotes, measured
path costs and the complete-panel collection cost are different quantities.
Training/collection/compilation costs and their amortization must be supplied from
actual receipts separately; offline replay does not simulate new executions or
charge the scientific ledger again.

The public entry is `examples/learn_policy_round4.py` with `fit`, `calibrate`,
`act`, `assess` and `evaluate` commands. `fit` accepts an explicitly supplied frozen config
and training JSON. `act` accepts policy plus ordered admitted receipts. `evaluate`
checks test release before opening test rows. No command searches the workspace
for labels. Hash/release checks are workflow controls, not OS access isolation.

Measured data require `--database` and a verified `taskrows` journal record before
fit/calibration/evaluation. `examples/assemble_rows_round4.py` constructs these
records from immutable pool admissions, settled resource costs, the coordinator's
released label file and its hash-pinned `experimental_order.py`. It calls that
oracle rather than implementing another assay-order rule. Every evidence string
becomes an actual hash-checked Artifact; placeholders in the JSON template are
intentionally non-runnable. The pure algorithm's fixture mode remains explicit.

`fixed_pool.two_chunk_catalog` implements paid initial `r0` (all six Vina scores),
query `q1/r1` (first three Vinardo scores), and `q2/r2` (last three). Each chunk
includes its own real setup/action cost. `subset_rank_outcome` checks pair orders
including 1e-6 ties and reports same/changed/failed; it rejects other-chunk scores.
Terminal Vina requires r0; terminal Vinardo requires r0+r1+r2. The common prefix
requires an actual receipt before `next_action` and is charged to every control.
`rows.visible_receipt` creates these visible histories from paid journal records.

`pool.py` and `examples/pool_round4.py` consume the new fixed-pool wire schemas
directly. They never reinterpret a request as an old graph-edit request. The CLI
requires the existing R4 database, reserves before dispatch, validates raw input,
result, artifact, slot and measurement identities, then settles actual cost once.
Previously settled producer-owned receipts retain their original body. Test
dispatch additionally requires a frozen request map and registered learned policy.

Each task row has `task_id`, `sample_unit="task"`, `independence_group`,
`source_kind` (`measured` or `synthetic_fixture`), `loss_definition`, `cost_unit`,
`outcomes`, `losses`, `resource_costs`, and `evidence`. The mappings
`outcome_evidence`, `loss_evidence`, `cost_evidence` bind each cell to declared
evidence IDs. Production adoption additionally requires actual artifact hashes
and ledger receipt binding; arbitrary strings in fixture input are not real
evidence. Input adapter details remain subject to the frozen producer contract.

## Scientific split and limits

The coordinator's initial R4 protocol uses nine protein families: train
mcl1/thrombin/ptp1b, calibration eg5/pfkfb3/pde2, test cdk2/tnks2/hif2a. Up to six
candidates per group contribute to a within-group experimental pair-order loss;
groups receive equal weight. Poses, seeds and the candidate pairs themselves are
not independent groups. Prepared poses restrict the claim to given-input workflow
selection. Unsupported cofactors/metals and unavailable labels remain visible.

Three calibration and three test groups support a small descriptive pilot, not
broad statistical calibration or transfer claims. The empirical model retains
joint support and external-model failure. The coordinator froze mixture weights
0, .25, .5, .75 and cost weights 0, .001, .01 before test access. Mixture selection
uses group Brier; cost selection uses loss + .001 times seconds, with smaller
parameter values breaking ties. The initial weight is .001, depth two, per-path
reservation cap 900 seconds and one global scientific ledger cap 1200 seconds.
Only actual receipts establish spending. Independent test evaluation is still
required after calibration-selected policy freezing. Copy-best and the static
schedule retain the original training model; myopic and exact/phi use the same
selected predictive model. The distinction is saved with the policy artifact.

## Released R3b diagnostic

`pose_selection.py` computes selected loss minus pool-optimal loss under the SAME
nearest-mode or worst-mode single-pose objective. It separately reports ensemble
coverage, scored/all-admitted pool optima, missing-score poses, tie ranges and
selection direction. `examples/diagnostic_pose_selection_round4.py` consumes
PRISM's already-computed fixed-pool report and the released independent distances;
it does not duplicate scoring, alignment or new reference generation.

The consumer's actual released-data check verified all 24 admitted pose hashes,
slot/score associations, per-mode distances and frozen selections. The eight
rejected slots remain in the attempted denominator. Same-loss regrets in A:

| Candidate/pool | Nearest-mode regret | Worst-mode single-pose regret |
|---|---:|---:|
| 2-methoxyphenol P0 | 0 | 0 |
| 2-methoxyphenol P1 | 0.1073436052 | 0 |
| 2-methylphenol P0 | 0.2025501995 | 0.5026429914 |
| 2-methylphenol P1 | 0.9505569062 | 0.4954941508 |

These are seen-feedback structural diagnostics, separate from the deprecated
R3b gap label and the experimental ranking endpoint. The proposed minimal next
intervention is Vina versus Vinardo score-only on the identical fixed pool and
receptor/state/preparation. It tests score-function sensitivity; eight aggregate
Vina columns cannot uniquely establish a solvation or receptor mechanism.

The coordinator subsequently audited the actual interventions. On the original
1LI2 receptor, switching Vina to Vinardo left every one of the four pool selections
unchanged. Reference receptor replacement changed P1 choices but also changed
SER38 to ASP38 and ASN144 to ASP144, so that comparison is composite.

The later geometry hybrid retained the original chemical atom identities and
passed the coordinator's coordinate, internal-distance and 161-peptide-bond
checks. It selected methylphenol P1 slot 8 and methoxyphenol P1 slot 7, giving zero
nearest-mode regret in both pools. Worst-mode single-pose regret did not also
vanish. The methylphenol scores were -6.064 versus -6.020 kcal/mol for the next
pose, a margin of only 0.044; methoxyphenol's were -3.051 versus -2.867. This is
stronger evidence of sensitivity to the receptor geometry model than the composite
replacement alone. The hybrid was not relaxed, uses default protonation and known
holo information, and does not establish a uniquely identified physical mechanism.
The failed first hybrid construction and its abnormal bond lengths remain in the
record. Coordinator evidence: `integration/round4/audit_interventions.py` and local
`round4/interventions-audit-v2.json`.

This diagnostic challenges a scorer-only account and remains in H/model
limitations. It does not add receptor choices to the current two-workflow pilot,
alter the frozen calibration grid, or tune a future receptor-query catalogue on
this batch's test tasks. Success of the bounded workflow policy would still not
establish a complete learned mechanism or RSI.

## Post-evaluation feedback and H

After the coordinator releases test evaluation and reviews its conclusions,
`examples/feedback_round4.py` attaches the missing cross-task policy feedback to
the existing `ResearchJournal`. It introduces no new Revision or validation type.
It requires the original ledger, calibrated policy, admitted test rows, frozen
online predictions, independent release, calibration selection report and released
seen-intervention audit. The release must bind policy, split and the exact
prediction file, either directly or through the coordinator's typed evidence list.

The attachment verifies registered train-to-calibration lineage and requires
offline phi's scores, decisions, query sequence and actual resource cost to match
the frozen online run. It records all six comparisons, probability/support scores,
all calibration selection candidates, and the receptor diagnostic limitation.
Calibration selection scores remain distinct from independent test scores.
Test rows and release retain `independent_validation` artifact roles; evaluation
feedback is thereafter seen and cannot validate a later revision as unseen.
No policy, prediction, grid or scientific observation is changed or promoted.

Support failure or no scientific-loss improvement over copy-best records
`diagnosis_required`. Other outcomes still require additional independent tasks.
The proposed next receptor-state/preparation diagnostic needs a new catalogue,
explicit cost and identity contracts, and fresh groups; this feedback authorizes
no dispatch or tuning on the current test panel. Source-quality challenges in the
curated assay panel must remain explicit rather than silently repairing labels
and refitting after test exposure.

Finally, `examples/archive_joint_feedback.py` snapshots the same ledger and verifies
all artifact identities. Its index includes the new `controllerfeedback-r4` record
alongside old failures, superseded policies and every execution receipt. This is
an archive, not a new campaign budget. Collection/retry and processing costs remain
separate from counterfactual policy path costs and need explicit amortization.

## Actual bounded R4 result

The corrected producer scored all 36 slots in each of TRAIN, CAL and TEST
successfully. TRAIN and CAL precede the frozen online TEST. TEST acquired eight
resources online and froze predictions before the ninth, counterfactual-only
resource was collected. The independent label release followed that freeze.
The consumer verified 877 corrected TRAIN delivery files, 960 CAL files and
834 TEST files by hash and size, and replayed the visible query sequence and
terminal decisions against the original online prediction artifact.

The calibrated policy queries q1: `changed` selects Vina, while `same` selects
Vinardo and pays the remaining r2 resource. It selected Vinardo for CDK2 and HIF2A,
and Vina for TNKS2. Equal-group held-out results are:

| Policy | Scientific pair-order loss | Actual path seconds/group |
|---|---:|---:|
| Initial fixed Vina (phi0) | 0.43418803 | 4.45874757 |
| Learned phi | 0.43076923 | 10.80431124 |
| Train-only copy-best | 0.60854701 | 12.02858371 |
| Fixed q1,q2 schedule | 0.67521368 | 12.02858371 |
| Myopic | 0.43076923 | 10.80431124 |
| Finite nonmyopic | 0.43076923 | 10.80431124 |

At the predeclared common tradeoff of loss + .001 times seconds, phi is
0.44157354 versus phi0's 0.43864678. The slight raw-loss improvement therefore
does not establish net benefit. Myopic and finite nonmyopic give identical
results on this pilot. These controls replay the same measured resource panel;
they are correlated comparisons, not separately executed independent runs.

Test marginal Brier worsened from 0.44444444 before calibration to 0.50694444
afterward. TNKS2 has the unseen joint outcome `(changed, changed)`: one of three
test groups is outside joint support despite nonzero marginal probabilities.
The static schedule pays both queries before abstaining there. The learned
online policy only sees q1 before selecting Vina. Both facts must be retained.

Total scientific spending is 175.68118975497782 wall seconds in the original
1200-second ledger, including failed/superseded engineering executions. This
collection cost differs from a policy's per-task path cost; processing overhead
and amortization require their own record. The conclusion is an executable,
conditionally transferring policy with unresolved model and cost limitations,
not reliable calibration, nonmyopic superiority, automatic promotion or complete
RSI. Subsequent diagnostics need fresh groups and explicit receptor/preparation
interventions; the now-seen test panel cannot choose new weights or a catalogue.

An append-only coordinator audit checked the six EG5 values against ChEMBL's
human recombinant Eg5 ATPase assay CHEMBL1101849. All six values and fifteen pair
orders agree. The curated DOI field was wrong; document CHEMBL1154988 identifies
10.1016/j.bmcl.2010.01.110. Original release bytes and fitted policy remain intact.
This source check does not upgrade the verification depth of other target groups.

The public feedback command subsequently ran in the actual Linux environment
from immutable consumer snapshot `etalon-pool-77dd09751ea6`, retaining all nineteen
pool/learning/online source pins. Two feedback tests passed there. Its second
invocation produced byte-identical feedback with zero additional journal events
or scientific charges. The final H02 snapshot, taken after feedback, contains
1044 research records, 518 artifacts, 1135 events and 45 execution cost receipts.
The consumer independently verified both delivery manifests (7422 and 1072 file
entries), all final-H artifact coverage, and the same-H feedback body against the
delivered JSON. The earlier H01 snapshot remains historical.

Separately recorded non-overlapping processing overhead totals 101.81272211670876
wall seconds and 100.871966161 CPU seconds. These are measured-interval lower
bounds; unmeasured development, transfer and archiving time is not zero. This
closes the implementation/evidence handoff for the nine-family pilot while its
scientific state remains `diagnosis_required`, with no automatic promotion.
