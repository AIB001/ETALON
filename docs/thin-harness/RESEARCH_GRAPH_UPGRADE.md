# 研究图、Memory 与 RSI：本轮升级入口

这轮把研究图上的记忆、方法参数、实际路线与宿主接续连接到已有薄层
harness。继续复用 ResearchJournal、Artifact、research-step、checkpoint、
MethodVersion / MethodUse / MethodEvaluation；没有新增研究账本或执行引擎。

这里说明已实现的接口和验收边界。具体运行是否通过、使用了哪个解释器和
源码、产物及耗时，以相应验收目录中的机器记录为准；本文不预填未完成的
验收数字，也不把接口存在写成科学收益。

## 一张研究图，三个能力组件，三类 skill

| 维度 | 本轮约定与实现 |
| --- | --- |
| 研究图 | Search / Judge / Quick / Deep 四个工作区，允许回边、跳过和局部展开 |
| Memory | 研究节点引用已有证据、判断、方法、执行和分支状态；共享证据不复制 |
| 能力组件 | MolQuarry、MolCascade、PRISM 多对多服务研究节点，不强制串行经过三层 |
| Memory skills | 整理当前决策上下文，读回来源、反证、经验和接续状态；写入复用 research skill |
| Execution skills | 使用组件、提出参数候选、检查交接与组合 workflow |
| RSI skills | 从具体问题提出修改，随正常执行评价，记录采用、保留、回退或证据不足及其适用范围 |
| 宿主与 hook | 宿主做科学判断；hook 处理可观测事件、读取与交付收据，不代替科学判断 |

MolQuarry 提供查询、目录和来源能力；MolCascade 提供准备、筛选、对接与
交接；PRISM 提供体系构建、MD、自由能等能力。这个分类不是一个强制路由。
Judge 通常由宿主完成，可以调用任意相关能力。

Deep 保留用户要求的含义：计算时间较长、费用较高、产物更丰富，也可连接
合作 lab。计算量和信息产量不自动等于科学可靠性或决策收益。旧记录未写明
资源模式时，投影不会因为组件叫 PRISM 就推断它属于 Deep；可以用显式
`home_overrides` 注明分区，并保留这是投影注释而非旧历史字段。

## Memory 的读取与接续

入口文件仍为 `{workspace, checkpoint_ref}`，旧研究不需要重写历史记录。

```python
from etalon.research.research_context import build_research_context

context = build_research_context("research-entry.json", max_bytes=16384)
```

MCP 提供 `etalon_research_context` 与 `etalon_research_graph` 薄入口。生成上下文
只读：不提交任务，不重试 pending，不改变分支，不授权执行。落档仍由已有
Journal / research-step / checkpoint 接口完成，生成的投影也可另存普通
Artifact，而不冒充新科学证据。

上下文优先组织当前节点、条件经验、显式反证关系、邻接节点和分支差异。
它保留来源水位、精确引用、检索策略、遗漏范围、claim 条件和局限。重复的
分支引用通过 `reference_index` 归一；有限字节预算不应把暂停和 pending 状态
挤掉。若控制元数据本身超过预算，接口明确失败。

反证关系两端都会进入选择候选；方向仍由原声明确定。B 引用 A 作为反证时，
不能倒推 B 反驳 A。若预算省略任一端或方向边，反证上下文的覆盖标为不完整。
没有找到合格反证时报告范围与缺口，不为满足比例而补造内容。

用途权限与“谁见过什么”分开。显式 policy 只能缩小已发布 workspace 的范围，
过滤发生在摘要生成前。此边界不替代文件系统权限或其他工具的授权。
历史 `as_of` 只支持与给定冻结来源匹配的视图，不重建 live Journal 的过去，
也不宣称一个 snapshot 就代表过去宿主实际掌握的知识。

## 参数、计划与执行分别留证

方法参数分为执行设置、方法／选择假设和外部评价定义。自由度、约束、
筛选阈值等可以成为修改候选，但不能通过放宽成功标准来宣称质量改善。
用户硬约束不由候选比较自行解除。

编译沿用 `Screen.plan`，记录声明、实际默认值、编译后配置与代码身份。
显式 parameter bindings 检查“写入配置的值是否到达执行阶段”。参数有匹配、
缺失或转换状态；未绑定或发生转换的修改需要补充证据，不能假设已经生效。

可比性检查面向必需检查的语义覆盖，而非工具调用次数相等：有依据的缓存、
复用和删除冗余步骤可以评价。缺少后端、遗漏必要检查或未经解释的实际程序
变化，不得被算成同协议提速。`ready_for_evaluation` 只表示可以进入既有评价
流程，不表示收益已成立。

四阶段 trace 保存声明、编译、执行与准入。宿主声明和执行端观测分开标记，
失败、拒绝、部分结果及未知费用不消失。重复事件可去重，但不据此宣称
跨系统 exactly-once 执行。路线 HTML 由同一份 trace 生成；它帮助人核查，
不保存完整私有推理，也不替代执行收据的真实性验证。

## RSI 如何沿正常研究发生

```text
已有问题与证据
    → 改进上下文和方法／workflow 候选
    → 参数契约与编译检查
    → 正常执行 + 四阶段 trace
    → 固定评价标准下比较
    → 采用 / 保留 / 回退 / 等待证据
    → 条件经验写入与后续检索
```

不存在新增的固定 Probe 阶段，也不存在“每落档一次就自动优化”的规则。
已有基线可以在条件匹配时复用；修改候选随正常执行形成可比较证据。经验
包含有效范围、负面结果、失效条件与 supersedes。没有提供当前匹配条件时，
读取器明确表示尚未核验新分支适用性。

Memory 策略、单个方法、分支选择、workflow 和组装方法可以使用相同版本及
评价机制，但收益需要分别证明。读取更多证据、成功编译、生成一张图或改变
一组参数，都不是统一的科学效果。内部目标改善也不等于姿势、亲和力或实验
效果改善。已有 SND1 经验仍保持其原来声明的范围。

## 验收与发布边界

示例脚本读取既有入口，并要求一个明确包含 `id,smiles` 的输入 CSV。新产物
进入新目录；旧 Journal 只读。它比较小型 CPU 属性计算中的参数消费和输出，
保存配置、编译、收据、评价、trace、路线 HTML 及新接续入口。单个有顺序的
计时对照不足以晋升提速方法；它不包含新 docking、MD、FEP 或 lab 验证。
具体执行命令、失败或成功状态以运行目录保存的报告为准。

现有不带研究入口的 host export 保持原有行为。原生 hook 通过显式导出研究
入口选择启用，不修改当前宿主的私有 memory、全局设置或现有服务。导出或
协议测试通过，只证明配置及适配器接口；真实宿主发现、执行和模型消费需要
分别验收，交付收据不会冒称“模型已经阅读”。

部署仍需固定源码与实际导入路径，保留旧任务所用环境和快照，重新校验包内
字节与固定 schema 哈希。新的本地代码或验收完成，不自动代表服务器已升级；
服务器部署状态以单独交付记录为准。

资源分配和调度不在本轮范围内。R4b 保持暂停，读取它的状态不代表恢复任务。
