# Optional RSI continuity

The thin harness preserves three identities: an exact opportunity event, a
reviewed defect family, and candidate content relative to its baseline. Four
ordinary Artifact schemas add annotations to the existing journal; no MCP tool,
store, scheduler, mandatory stage or model invocation is added.

| Existing path | Addition |
| --- | --- |
| `register_opportunity` | Recover no-change/retained terminal states, waiting and reviewed reopening; optional family reuse |
| `record_content` and publication | Validate original-linked family, disposition/reopen and candidate-brief content |
| Research graph and context | Project annotations in Judge; checkpoint tail outputs point to exact originals |
| MethodEvaluation and experience | Keep original measured authority; no evaluation is fabricated for no-change |
| Entry/checkpoint/hook | Deliver ordinary appended research data through the existing continuation path |

The original `/1` opportunity key and first request ID are unchanged. A recorded
reopen derives a new episode request ID. This is not exactly-once LLM execution:
the caller must use its existing idempotent request consumer. The SDK does not
launch a proposer. An incomplete or conflicting history cannot be interpreted as
an untouched opportunity.

Family reuse is explicit. Scope, conditions and task must match; accepted
membership alone does not prove current applicability. Reference-only relations
never close another task. Unchanged original inputs may reuse a terminal judgment;
changed evidence needs reconsideration. Previous negative and conflicting reviews
remain accessible.

Candidate identity excludes display title/rationale, but binds baseline, target
part and intended content. Evaluation, execution and adoption remain separate.
The normal-execution discriminator reuses the existing task and evaluation
contract; there is no fixed Probe. A completed comparison is read back, not rerun
because its brief was created later.

See [defect families](DEFECT_FAMILY.md), [opportunity states](OPPORTUNITY_STATE.md)
and [candidate briefs](CANDIDATE_BRIEF.md) for API contracts and bounded-read limits.
The SND1/PoseBusters acceptance is retrospective engineering validation over
archived actual runs. Reconstructed evidence arrival is not new independent
scientific evidence, and does not establish improved poses, affinity or transfer.
