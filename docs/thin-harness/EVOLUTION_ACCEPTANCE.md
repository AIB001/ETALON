# 演化与证据复用验收

日期：2026-10-21。以下是事前标准，不是通过报告。工程与收益分别给 passed/failed/not_run/blocked/inconclusive，保留全部尝试。产品契约见 [EVOLUTION_CONTRACT](EVOLUTION_CONTRACT.md)。V 独立制定具体任务、预期事实和评分规则，I 绑定实际源码/安装版本；评价脚本不成为产品 workflow。

## 2. 新 chat 的真实证据复用

REUSE-REAL：由 V 选择两个实际仍有价值的任务，候选为“依据既有 research 使用/反馈/对照证据提出可执行后续修改”和“迁移一个真实释放档案并核对身份、成本与限制”。任务不能是为新接口定制的假题；答案应对当前项目有用。V 可替换候选，但需在任何正式尝试前冻结理由和正确性标准。

每任务 original/current-baseline 与 evidence-enabled 各一次，共至多四次正式原生运行。两条件给等价已释放资料、相同任务、模型/工具/预算；差别只在项目入口与新检索/读取能力。原版可用正常 shell/SDK 查找，不人为削弱。新 chat 不继承实现 chat/审查答案或私人 memory；只给任务和正常项目入口，不在提示中规定先 query、必须读 skill 或最终答案。失败题不补跑。

观察：能否找到必要事实/反证、引用精确原件、正确区分历史/未验证/暂停、完成实际产物；以及读源码次数/字节、无关遍历、shell/MCP 调用、input/cached/output、wall、未知费用。找到资料但误解也算质量失败；跳过 skill 但高质量完成是合法成功。仅返回变短不证明 token 节省。

工程通过要求目标证据链可实际读用且关键质量项通过；效率收益单列。若条件不同、缓存无法控制或某次费用缺失，只报告范围和不确定性，不补造成因。保留 baseline 较优或无差异结果。

## 3. 元 skill 自身改进的真实任务

META-SELF-DEV：B 必须实际读取并使用 G0，在已释放开发轨迹上产生 G1，保存这次原生 chat 的输入、调用、修改、完整快照及成本（不可得为 unknown）。可用历史 E2 未采用/反复翻源码等问题，但不得读取 V 后续评价材料。仅人工代写 G1 或生成演示 fixture 不满足此项。允许 no-change；此时如实说明未形成 G1，不伪造自身改进。

META-PRODUCE：V 事先选择并封存两项不同于开发问题的真实方法改进需求与评分依据，G1 固定后才向生成任务释放；不得按 G1 内容或试跑结果挑题。分别让 G0/G1 对同一旧方法、同一可见证据和同等预算生成候选，共至多四次正式原生运行。固定 G 是评价干预，不是产品强制路由。保存 G、被改 S/U、候选与生成调用的精确关联；没有候选亦保留。

META-TRANSFER：每个生成候选在对应新的实际使用任务中运行一次，共至多四次。宿主可以采用、部分用、组合或跳过；不得用“必须用候选”的提示伪造自然采用。控制宿主/工具/任务起点和使用指引；若候选被跳过，区分系统整体结果与候选实际效应，不能宣称后者已测。no-change 用原方法执行而非丢组。

V 在执行前定义关键质量项、成本统计、接受差异和适用范围，独立检查原件。评价 G 的对象是后代方法的质量/总成本/泛化，不是 G 自我评分或生成数量。含开发、候选生成、所有失败及后续使用成本，分别报告共同开销和摊销。不能在暴露结果后改指标、挑最好候选、增加重试或让 G 改裁判。两任务只支持有界工程 pilot，不能宣称广泛 RSI 或科学收益。

## 4. 资源与冻结

初始正式尝试总上限十二次：REUSE 四次、META-PRODUCE 四次、META-TRANSFER 四次。G0→G1 的 B 开发 chat 单列实际开发成本，不作为免费的“未调用模型”。每正式尝试 wall 上限 300 秒、累计 input（含 cached）上限 400000；合计预留最多 3600 秒/4800000 input，不是实际消费或金额。I/V 可在首次运行前缩小设计，不可看到结果后扩大或补跑。工程协调 chat 费用另计，不把此正式预算冒充整个项目费用。

原生 runner 需记录并执行可实现的限制；token 超限若只能事后发现，保留超限事实并判预算失败，不能声称硬界未超。输出 token、网络/安装成本、金额未知分别保留。使用现有可用宿主及环境，不下载模型、不调 Jev/Laya、不更换共享依赖、不执行 PRISM 评分或 CRO 订单。Claude 认证阻塞独立记录，无需以重复登录尝试阻塞其他工作。

正式运行前 V 写任务/配对/评分/隔离/预算 freeze，I 写 source+wheel+runtime pins 和 READY；二者是本批评价的工程准备，不是任何产品调用的 method gate。原生验收只能由 V 指定的一名 runner 写其 runs 目录；实现线不得补跑。遇上限或 blocker，保留结果继续完成能独立完成的工程工作。

## 5. 最终材料

源码起点与最终 diff；安装/导出核验；每次原生 launch、实际 import、原始调用和产物、失败/超时；方法及证据引用映射；完整成本与未知；冻结前后顺序；保全清单；分项工程/行为/收益结论。R 审查这些材料，不以测试数量或候选版本数签收 RSI。没有改进证据时结论应是 not_established/inconclusive，不能为得到 passed 再加固定流程。
