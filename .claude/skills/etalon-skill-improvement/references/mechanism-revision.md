# Improve how the task finds a better method

Use when the current improvement strategy keeps optimizing a proxy, repeating an
uninformative experiment or changing the wrong operation. An ordinary parameter
adjustment need not create a third-layer revision.

Start from a useful output the task still lacks. Separate the observed discrepancy
from competing explanations. Read only the rule dependencies and originals that
can change the next action. `action_learning.gather_rule_revision_context` joins
normal feedback to the existing research model's prediction bindings. It retains
unknown and unbound predictions; dependency paths nominate assumptions, not causes.

Choose a concrete change to the second-layer procedure:

- Split an overbroad inference into conditions where its proposed action differs.
- Change the action representation when existing degrees of freedom cannot alter
  the target. For geometry, distinguish rigid motion, torsions and chemical edits.
- Change an internal objective, candidate population, selection rule or execution
  order when those choices hide useful actions. Preserve the external endpoint
  and distinguish their effect from a stronger solver for the old objective.
- Combine compatible operations into a program that runs without asking the model
  to reinterpret each known intermediate. Return at a scientifically new residual.
- Use a discriminating observation already available in normal outputs before
  buying another calculation. New independent repetition is useful when variation
  is the unresolved question; it is not duplicate execution of the same request.

An improvement may remove a computational path or substitute a cheaper method.
First identify what the omitted result could change. An exact derivation can make
the same decision without the old computation; scoped evidence can justify a
conditional substitute with its uncertainty retained. For example, a strictly
increasing objective transform preserves an exact minimizer on the same feasible
set, but does not equate the numeric scores or approximate solvers. Record the
conditions, evidence, exceptions and outside-scope fallback in task memory; put
repeated condition checks and execution in code. Reuse unchanged checks. Do not
force a costly comparator when it cannot distinguish the live alternatives. When
fidelity is unresolved and could change the action, use the relevant comparison
or keep the replacement exploratory. Omitted outcomes remain unmeasured, and a
scoped decision equivalence does not establish equal physical predictions.

For example, failure of a constructed contact after relaxation may implicate its
direction, intramolecular strain, environment preparation or a different binding
mode. Earliest contact loss can change which operation to try next. It does not
prove the earliest stage is the unique cause. A fortunate final frame or a lower
internal score alone does not establish a better physical pose.

Write the revised choice procedure in the existing skill reference or task-local
method, then actually use it. Learned conditions and opportunities remain in task
memory with their original evidence; scientific operators remain in code.
Link G's version and generating use separately from the
S/U candidate's parent method. A third-layer candidate succeeds through the useful
changes its descendants produce, not by issuing more candidates or declaring its
own diagnosis correct. A retrospective comparison can motivate a trial, but does
not establish a prospective selector advantage.

After a negative result, retain/no-change or a completed phase, choose useful work
for the still-open scientific question. Reuse a known path immediately when it
fits; revise the improvement procedure only when its limiting assumption changes.
These are possible choices within ongoing research, not fixed execution, review
and improvement stages. The host remains free to change explanations and experiment.
No all-rules settlement, mandatory Probe, automatic model promotion or global
router is introduced. A locally retained failure can coexist with continuing branches.
Use the ordinary method-revision, experience, publication and work-object APIs
when they help the next host continue; do not assemble a separate learning store.

For execution continuity, a producer may return a compact result to
`research_segment.run_segment`: measurements, decisive examples, denominators,
residual questions, original references and an optional ordinary next command.
The command is a useful default, not a replacement for host judgment or authority.
An unchanged completed operation is reused. Changed inputs, methods or independent
seeds are distinct scientific actions when they answer a new question.
