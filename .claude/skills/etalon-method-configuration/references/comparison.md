# Configuration and comparison

Use `method_contract.validate_contract` to check the parameter contract and
`compare_parameters` to expose changed fields and classes. Compile each candidate
with `compile_screen_revision`; pass the actual input identities, conditions,
stage/check bindings and evidence bindings. Treat those bindings as declared
until execution receipts corroborate them.

`assess_comparability` reports whether the supplied comparison conditions support
the stated mode. It does not score a molecule, infer an unobserved branch result,
or certify scientific benefit. Keep evaluation contract changes explicit and
separate from comparisons under the original contract.

Four trace phases retain the declaration, compiled plan, actual execution and
admission decision. Agent decisions and hook observations have different origins.
A receipt-backed reused result is not a new independent repeat. Rejected results
remain in the history with their failures and actual costs.

For SND1-style changes, preserve molecular/state/atom identities and distinguish
hard-fixed atoms, soft restraints and directional interaction assumptions. Link
the scientific input and the actual consumption receipt; merely listing a paper
in context does not show that it affected method parameters.
