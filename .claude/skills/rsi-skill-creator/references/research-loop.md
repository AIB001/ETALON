# 从规则学习到行动的 RSI skill

当任务需要从正常运行中学习规则、改善方法或选择时使用。以下是可选择的机制，
不是每次科研都必须执行的阶段；本文件不提供新的执行器。

## 生成可用的策略

从当前决策和已有领域知识出发，找出影响选择的状态、可改变操作、目标和完整成本。
保留改变科学含义的区别，如化学状态、可动自由度和评价端点；避免只围绕某个靶点名检索。

候选规则应表达可观察差异：适用时预测哪个量或关系，结果会使哪条行动继续、改变或停止。
能编码且重复使用有价值时，复用执行接口运行局部 predictor / checker；只需一次的判断
可以保持带来源的科学判断。预测是预期，不是新的真实实验结果；未知不必强行数值化。

优先考虑能改变问题结构的改进：

- 分离固定结构和变化状态，编译局部操作，避免重复解析、推理或计算。
- 分解复杂方法，组合兼容操作，省去可由已有结果推导的重复步骤。
- 将多条同构规则参数化，或将失效的宽规则拆成条件更清晰的局部规则。
- 利用当前判断的依赖，选择可能改变行动的观测，复用正常执行中的评价机会。

预测失配时，沿输入/解析、规则、实现、观测和评价的依赖定位差异，不机械认定算法失效。
反馈不仅给出 pass/fail，还应呈现未解释的相关结果、互相冲突的预测和适用范围外的案例。
这些是下一步研究线索，不是必须清空后才能继续所有分支的阻塞清单。

## 配套能力与薄层边界

在生成的 skill 中点明已有能力的生产和消费关系：
局部上下文 → 规则/预期 → 方法或行动 → 实际结果 → 判断更新 → 下一次选择。
已有充分证据时可跳过中间步骤；没有独立预测器也可以由宿主提出可核查预期。
代码负责身份、差量、结果抽取与可重复计算；宿主负责科学解释、探索和取舍。

按任务需要提供可恢复的当前规则版本、待完成动作、已完成结果及继续条件，
不让新 chat 从历史叙述中重新构造全部研究。hook 交付这些状态与变化，不暗中执行科研。
同一规则用于提出候选和评价时，外部质量端点仍需独立，防止只优化自定分数。

规则、解析器或共享代码改变时，复用依赖未变的检查，重新处理受影响部分。
缓存应覆盖实际传递依赖；改变适用范围后仍保留原反例及其处置，不能通过不适用掩去缺口。
分子计算常有噪声、状态不全和延迟反馈，可用区间、趋势或条件判断，无需模拟确定性游戏。
