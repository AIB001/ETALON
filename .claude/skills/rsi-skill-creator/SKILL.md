# 创建 RSI skill：第三层

产物是一份可被 agent 调用的 **第二层 RSI skill**。它教 agent 如何改进，
而不是直接交付一次分子计算、一个第一层 skill 补丁或一段研究总结。

本约定的三层是：

| 层次 | 作用 | 示例产物 |
| --- | --- | --- |
| 第一层：执行 | 完成研究中的操作 | 对接、求解、证据检索、workflow 执行 |
| 第二层：RSI | 根据实际问题改进操作或选择方式 | 求解器改进 skill、分支选择改进 skill |
| 第三层：本 skill | 为问题类创建或修订第二层 RSI skill | 第二层的 SKILL.md、必要参考和评价办法 |

例如，“修复一次求解器”是具体改进；“如何从求解轨迹提出并比较求解器修改”
才是可生成的 RSI skill。层次表示作用对象，不代表三个强制执行阶段。

## 根据课题设计改进方式

生成的改进方法应能直接调用科学能力。普通比较留一条含条件、结果、成本和反证的
研究笔记即可；实际需要细粒度归因时再展开完整改进图。不要让创建 context、
opportunity、patch 等记录成为执行前提。课题参数和实验配方留在课题文件中。

改进结果可以分别落成计算代码、可调用 method、参数或运行配置、优化后的使用 skill、
条件性 memory；用现有笔记的 resources 引用把这些层次关联，不复制成多份方法库。
本 skill 只在改进程序本身需要创建或修订时介入，不要求每次尝试生成新的 SKILL.md。
下游可用性应由独立上下文实际找到并调用方法来检验，不能以文件存在或生成数量代替。

先理解用户要提高的研究能力、当前瓶颈、可改变的对象和已有改进方式。
利用已有证据、失败轨迹和技能库定位问题；信息不足时明确假设，仍可产出待试用版本，
无需为了写 skill 先启动一轮科研实验。

当现有改进策略反复错过收益、围绕错误瓶颈试错，或课题条件改变时，考虑修订第二层。
当代理指标持续改善而下游研究没有获益，检查第二层的动作表示、候选形成与反馈选择。
允许联合改变相互耦合的自由度、选择另一科学假设，或把已理解的操作合成可执行方法。
修订应改变后续实际行为；具体案例和失败轨迹留在 memory，避免扩大 skill 正文。
普通的一次方法修改可直接由现有 RSI skill 完成，不必先调用本生成器。

选择对当前问题有用的改进机制。例：重复求解的瓶颈可能适合局部算法改进；
分支漏救回可能适合执行前特征与有界备选比较；频繁检索遗漏可能适合上下文选择改进。
不要把这些例子固定成全课题通用流程，也不要因为“RSI”一词自动加入搜索、训练或 Probe。

候选也可以改变问题表示：分离不变量与变化状态、预计算局部操作、分解与组合方法，
或将过宽规则细分。选择能减少当前课题试错的机制，不强求跨课题通用算法。
需要从观测学习规则、用预测选择行动时，读 [研究闭环适配](references/research-loop.md)。

检查现有 RSI skill 是否能直接复用、只用某部分或做小幅适配。已有内容适合时，
说明采用范围；需要独立入口时再创建新的 RSI skill。尊重用户明确要求的新产物。
生成的 skill 要有自己的适用条件和改进机制，不能只是重述本 skill。

确认这份策略依赖的实际连接：谁提供当前状态与局部经验，谁执行预测或方法候选，
谁将结果送回判断、评价和后续选择。复用现有相关 skill 与 harness 接口；缺连接时，
说明生产端、消费端和最小适配，不能用文字指令冒充已有运行能力。
系统改造依当前任务授权实施；单独交付 skill 时明确尚缺的连接，不扩展成强制全局流程。

## 让生成的 RSI skill 可执行

用简短指引让下一位 agent 能实际作出以下判断；它们是内容要点，不是固定阶段：

- **何时值得改进。** 指明具体症状、相关输入、已完成工作，以及何时直接继续研究。
  新 chat、被读取、新版本号都不单独构成触发条件。
- **改什么、怎样提出候选。** 明确可调对象、可使用的证据、候选形成办法和因果预期。
  写出问题特有的选择依据，不能只说“分析问题，迭代优化”。允许不改动、直接使用 SDK、
  复用合格结果；未被采用的 skill 不自动成为内容缺陷。
  预测有助于选行动时，指出哪些可能结果会改变选择；使用已有理论、算法和经验，
  无需每个课题都从零建立世界模型。历史实例留在 memory，可执行机制留在代码，
  skill 保留改进办法和按需引用。
- **怎样判断值不值得。** 选择与当前决策相匹配的收益和质量要求，区分探索试用与默认采用。
  不要求提前预测尚未亲历的优化价值。通过有信息量的正常尝试逐步判断下一笔投入，
  将未探索、失败但有认识、已反驳和暂缓分开；允许改变动作表示后重新尝试。
  同时考虑误推进与漏掉好分支，计入生成、试用、失败、验证及后续使用成本。
  不用通过检查数、skill 数量或自我评分代替研究收益，也不把未知成本记成零。
- **怎样利用结果。** 根据证据采用、局部采用、保留、回退或继续观察；保留适用条件、
  负经验和有意义的重开条件。沿现有 memory、评价和版本接口落档，不另建账本。
  暂缓改进不等于终止课题；继续使用成熟方法推进研究。稳定操作批量执行，仅在
  新结果、规模或需求改变选择时唤起改进，不安排逐步审计或每次读取后的独立 judge。

生成的 RSI skill 应沿用课题的定义身份与选定资源部分：指标、分母、对象状态及
评价端点不能靠同名匹配。方法可以自由变化，外部评价定义保持可辨认；跨课题的
经验先明确哪些定义适用、哪些无关或未知。新执行方法从真实运行变量交付结果，
把观测、规则判定和宿主解释分开；定义只保存一次，运行记录实际取值和引用。
需要 ETALON 具体接口时按需读取 research skill 的 `references/result-meaning.md`。

可靠性要求服务于研究决策。身份、来源、可见信息边界和真实执行记录持续保留；
采样量、比较规模和确认强度按阶段选择。允许在已有授权内先试用一个未充分确认的候选，
清楚标记其范围和未知，不把“尚不能正式采用”误写成“不能探索”。

优先利用正常执行中的评价机会，复用身份及依赖未变化的已完成检查；改变的部分按需验证。
选择或省略内部步骤时，说明评价覆盖如何变化；采用同一外部端点比较真实质量和总成本，
不能通过放宽成功标准制造收益。不要新增固定 Probe、强制全流程或全局路由器。

## 第三层自身如何评价

写出第二层 skill 只证明产物已经创建。其后应观察：它提出的修改是否实际被用到，
在相同研究目标和可比预算下，相比原 RSI 方法或直接复用，是否带来更有用的研究结果。
局部任务收益可以成立；跨任务迁移是另一个需要验证的主张。
若收益依赖多个 skill 或运行接口适配，验收其实际贯通：新结果是否改变后续行动、
能否恢复并复用已完成工作。接口已连接与研究已获益分别报告，不能只验证新文本存在。

将“生成的 skill 好不好”与“本生成器是否更好”分开。一次下游成功可支持局部使用，
不自动证明生成器普遍优越。评价生成器时比较后续任务中的候选质量、漏掉的机会及完整成本，
保留生成器版本、实际生成调用与子 skill 的对应关系。无需先完成此评价才能交付候选。

本 skill 可以提出自己的修订候选，但新文本不会自动激活递归改写或扩大执行预算。

## 交付

按用户指定位置和现有技能库约定创建第二层 skill；保持入口短、描述准确，
仅在确有需要时添加参考资料或脚本。沿用可用的通用 skill-creator 进行文件格式和结构校验。
修改现有 skill 时保留基础版本，交代改动依据及适用范围；避免覆盖其他 chat 正在写的文件。

交付时说明：新 skill 面向哪类改进、一次典型调用、当前是待试用还是已有下游收益证据。
确认尚未执行的部分即可，不为每个产物要求额外登记或审批流程。

在 ETALON 中需要落档、评价或工作集接入时，再读
[现有接口与层次映射](references/etalon.md)。普通 skill 创作不强制先读完整研究库。
