# Research methods on demand

Choose the part that answers the current question; none is a prerequisite for
another. Known SDK calls can be used directly without skill discovery, method
registration, policy fitting, or the historical R3/R4/R4b scripts.

Continue toward the scientific objective after each useful result. A completed
phase, published note, negative result or retain/no-change decision does not by
itself finish that objective. Use learned conditions and remaining opportunities
to choose the next useful authorized action. Execute known methods directly,
reuse matching completed requests, and batch understood conditional followups
in code; return to model judgment when a new residual changes the choice.
Feedback can change the next question or action without creating a new method.
Change or skip a computational path when an exact derivation or scoped evidence
shows the cheaper path preserves the required scientific decision and quality.
Keep its applicability, exceptions and fallback explicit; an omitted comparison
is not a measured result. Existing pauses, budgets and completion conditions apply.

For an ordinary note entry, start with the task's installed interpreter:
`python -m etalon research current --entry ENTRY.json`. Read a known omitted field
with `research detail --entry ENTRY.json --record-id RECORD --select /field`.
Save changed knowledge with `research progress --entry ENTRY.json --patch PATCH.json`;
the JSON contains only fields to replace, and all omitted fields are retained.
These commands reuse the SDK below and require no source inspection or Probe.
For a known callable, use its declared inputs, parameters and pinned source;
inspect implementation when adapting it or resolving a concrete mismatch. Reuse
saved per-case results before computing them again. Load selected arrays once
inside the calculation, not through repeated model-facing reads.
Append an original with `progress --evidence RESULT.json` or
`--counterevidence CHECK.json` (repeat as needed). The command preserves prior
references and computes identities; ordinary progress needs no manual hash list
or readback of the old evidence array.

Keep complete execution/reuse receipts on disk. Bring the scientific result,
status, exceptions, relevant cost and exact receipt path into context; expand
specific receipt fields when they affect the decision. When the reader or reuse
interface has already verified the cited originals, routine continuation needs
no second traversal or printed manifest. Still read the bodies of relevant
counterevidence when they could change the scientific judgment.

Each reference distinguishes pure calculations, append-only records and external
execution. The reusable [synthetic SDK example](scripts/research_methods.py)
exercises transfer, partial use, paid-subset composition, failure-based stopping
and pose diagnostics locally. Run it with an interpreter containing ETALON;
it reads no scientific files, calls no producer, and writes only an explicitly
requested output JSON. Its callback costs are declared fixtures, not measurements.

Preserve molecule/state/pose/receptor/protocol identities, failure and unknown
states, original receipts and incurred costs. A missing counterfactual is not
zero. A model result is conditional on its declared support and grouping; it
does not establish a chemical mechanism, independent performance, or promotion.
Keep unsupported conclusions provisional and choose a useful next observation
when authorized; missing support alone does not end exploration. Do not invent
worlds or silently dispatch a retry. Existing pauses and resource limits apply.

For `bind_outcome`, `condition`, `exact_program`, `empirical_model`, factorial
contrasts and recorded program compilation, use the existing `etalon-campaign`
references. They remain independent methods; this entry does not replace them.
