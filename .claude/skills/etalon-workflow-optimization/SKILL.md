# Improve workflow and branch choices

Use when normal results indicate the research sequence, branch choice, method
combination or an avoidable handoff is limiting progress. Start from the live
scientific question, decisions still open, available evidence, applicable task-local
experience, and the actions already running or completed. Retrieve only material
that can change this choice, including relevant counterevidence.

Consider reordering, combining or bypassing operations, choosing a branch, reusing
an existing result, reopening a failed branch under changed conditions, or keeping
the existing workflow. Methods and whole research layers are optional when their
outputs are unnecessary for the current decision. A cheaper path can replace a
costly one when a derivation or relevant scoped evidence supports the required
decision and quality; state its scope and fallback. Unknown unexecuted alternatives
remain unknown, not zero-value failures.

When useful and authorized, compare a bounded set of alternatives through normal
execution, including both needless advancement and prematurely lost promising
branches. Preserve the inputs, decision meaning and necessary checks when claiming
an equivalent outcome. Compare elapsed time, compute and model costs where known;
do not interpret fewer nodes or calls by itself as scientific improvement. There is
no fixed Probe, compulsory agent call at each node, or global workflow router.

Use existing action, method, feedback and research-memory interfaces. In the current
task note or research step retain the selected path, actual execution, relevant
skips and their conditions, output, useful negative experience, cost and next action.
Record when a changed condition or new evidence makes reconsideration worthwhile.
Do not record skipped branches as measured outcomes or create a separate ledger.
